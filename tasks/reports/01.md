## Deviations from the spec

- **Extra setup rejection.** `createGame` returns `INVALID_SETUP` in three cases the spec doesn't list:
  - a player id that is empty or not a string;
  - a team other than `A` or `B`;
  - with a fixed `deal`, an explicit `firstPlayer` who holds no cards.
- **Random first player** is picked only from players who hold cards. The default deal gives everyone cards, so in practice this matches "random player". It only matters for fixed deals that leave someone empty.
- **Unknown `action.type`.** It can only happen if the input skips type checking. It returns `WRONG_PHASE` with the message "Unknown action.", because the contract has no better error code.

## Assumptions

- **`structuredClone`** is assumed to exist at runtime (Node 17+, modern browsers). The ES2022 lib doesn't declare it, so `clone.ts` declares it locally to that module. Consumers' globals are not affected.
- **Rejected actions are not cloned.** Validation reads the input state; cloning happens only once an action is accepted.
- **`declared.assignment`** in the event is a normalized copy that holds only the set's 6 keys, in set order.
- **Event arrays are copies.** `chooseRequired.eligible` and `chooser` are copies, so callers can't change `state.phase` through an event.
- **Assigning a card to an empty-handed teammate** is a well-formed declaration. It is scored as wrong, not rejected.

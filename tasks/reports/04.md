# Task 04 report: accounts

## Built

- Idempotent SQLite schema and migration for users, finished games, game participants, and the participant lookup index.
- Web-standard Discord OAuth login/callback, opaque ten-minute state cookie, callback state validation, profile refresh, generic upstream failure responses, and HMAC-SHA256 signed 30-day sessions verified with `crypto.subtle.verify`.
- Current-user lookup reads the latest profile from SQL and returns `null` on every failure. Logout expires the session cookie.
- Idempotent finished-game writes, aggregate player stats, and a leaderboard sorted by wins, win rate, and display name.
- Minimal Cloudflare D1 adapter and Node-only `better-sqlite3` adapter with WAL mode and automatic migrations. Exported the Node adapter at `@litt/accounts/node` without importing it from the Workers-safe package entry.
- In-memory SQLite integration tests, injected Discord and clock tests, session tamper/expiry tests, privacy checks, and fake D1 tests.

## Discord setup

1. Create an application in the [Discord Developer Portal](https://discord.com/developers/applications).
2. Copy its Application ID and client secret.
3. Under OAuth2, register `http://localhost:8787/auth/callback` and the production callback URL.
4. Configure `DISCORD_CLIENT_ID`, `DISCORD_CLIENT_SECRET`, and a high-entropy `SESSION_SECRET`. Set `PUBLIC_BASE_URL` to the externally visible origin in production. `DATABASE_PATH` selects the Node SQLite file and defaults to `./litt.db`.

## Security and deviations

- OAuth callback failures return a generic plain-text 502. Tokens, authorization codes, and secrets are not logged or stored.
- The `next` redirect is resolved against `publicBaseUrl` and limited to the same origin, including protection from browser-normalized backslash paths.
- `recordGame` uses `INSERT OR IGNORE` for both the game and player rows; duplicate record ids do not double-count.
- The injected DB contract has no transaction or close method. The Node factory returns a `BetterSqliteDb` with an additional `close()` method; callers using only the `Accounts` interface retain the contract unchanged.
- No dependencies were added; the existing `better-sqlite3` installation was moved from development to runtime dependencies and the workspace lockfile updated.

## Assumptions and open questions

- Session expiry is encoded as Unix epoch seconds, matching conventional cookie/session payloads; the injected clock is in epoch milliseconds.
- OAuth state and its sanitized redirect destination are stored together as base64url JSON in the HttpOnly state cookie; the random 32-byte state is independently sent to Discord.
- Win rate uses wins divided by games played, with draws included in games played.
- Production callback origin/proxy configuration must match the registered Discord redirect URI exactly.
- Hosting and D1 deployment wiring remain part of the later integration task.

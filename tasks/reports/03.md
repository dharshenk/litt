# Report — Task 03: Web client (`@litt/web`)

## What was built

A React 19 + Vite client rebuilt from `design/` (not ported). It is driven only by `PlayerView`, `RoomSnapshot` and `ServerMessage`. It imports only `cards.ts` helpers and types from `@litt/engine`.

| Area | Files |
|---|---|
| Setup | `index.html` (Google Fonts, inline SVG favicon), `vite.config.ts` (proxies `/api`, `/auth` and `/ws` to `:8787`; Vitest uses jsdom), `tsconfig.json` |
| Theme | `src/styles/global.css` holds every design token. Dark is the default. Light applies under `prefers-color-scheme: light` or `:root[data-theme="light"]`, and `data-theme="dark"` forces dark. It also covers reduced motion. |
| HTTP | `src/lib/api.ts`. `apiUrl()` and `wsUrl()` are the only places that append `devUser`, and they do so in dev builds only. |
| Connection | `src/net/RoomSocket.ts` is framework-free: JSON in and out, 0.5s→8s backoff, a ping every 25s, and it stops for good on `replaced`, `ROOM_IN_PROGRESS` or `ROOM_NOT_FOUND`. `roomState.ts` is a single reducer over `ServerMessage`s. `useRoomConnection.ts` wires them together. |
| Rules mirror | `src/game/legal.ts` holds the pure ask and declare legality checks, in the engine's check order. They are used only to disable illegal options. |
| Pages | `pages/Home.tsx` (login, create or join a room, dev login, leaderboard). `pages/RoomPage.tsx` (login gate, joining and closed states, reconnect banner, event → spotlight/toast/sound pipeline). |
| Room | `room/Lobby.tsx`, `room/GameOver.tsx` |
| Table | `table/Table.tsx` (layout, phone bottom bar and sheet), `Header.tsx` (status pill, timer ring, mute), `Board.tsx` (player rows, sets), `Hand.tsx` (deal and received-card animations), `Panel.tsx` (ask, declare, choose, waiting, transfers), `ReviewModal.tsx`, `AskSpotlight.tsx` |
| Sounds | `src/lib/sound.ts` uses Web Audio oscillators only. The mute setting is stored in `localStorage` inside a try/catch. |
| Mock mode | `src/mock/` holds the fixtures, an in-browser fake server that speaks the real protocol, scenarios and the **PROTOTYPE** panel. It is loaded on demand as its own ~15 KB chunk, so it is not in the main bundle. |

## How to run

```sh
npm run dev -w @litt/web           # http://localhost:5173, proxies to the server on :8787
# Mock mode, no server needed:
#   http://localhost:5173/?mock=1   (sticky for the tab; ?mock=0 turns it off)
#   or VITE_MOCK=1 npm run dev -w @litt/web
npm run typecheck -w @litt/web
npm run build -w @litt/web
```

## Deviations from the design

- **Start-reason order.** The checks run in this order: fewer than 6 players ("Need at least 6 players. Share the invite link."), then unassigned players, then unequal teams. The prototype checks unassigned players first. With only 3 people in the room, "Need at least 6 players" is the more useful message.
- **Declare picker.** Teammates who are out of cards are disabled, with an "Out of cards" tooltip, since they can't hold any card. The assignment is still legal; this is only a UI hint.
- **Toast after a failed ask.** No `turnChanged` toast is shown after `askFailed`, because the spotlight already says "… — Bob's turn". After `timedOut`, the next `turnChanged` is merged into a single toast, e.g. "Time's up for Bob. Priya's turn."
- **Phone choose sheet.** It opens automatically when you are the chooser, but it can be closed and reopened from the bottom bar. In the prototype it can't be closed.
- **Extra screens the design didn't cover:**
  - a room login gate, for invite links opened while logged out;
  - "Joining room…", which becomes "Can't reach room X" after 3 failed attempts;
  - closed states for "replaced" (with a **Use this tab** button), `ROOM_IN_PROGRESS` and `ROOM_NOT_FOUND`;
  - "Dealing…" while the room is `playing` but no view has arrived yet.

  All of them use the existing type and colour tokens.
- **Tile tags.** Besides "Playing" and "Out of cards", tiles can show "Asking" (the opponent picked in my ask panel) and "Choosing" (the named chooser).
- **Suit glyphs** carry U+FE0E so that ♥ and ♦ never render as emoji.
- **Errors toast icon** is "!" rather than the prototype's "•".

## Assumptions

- **Game-over delay.** If the game ends while you're watching, the table stays up for 1.8s, as in the prototype, before the game-over screen appears. On reconnecting to a finished room it appears at once.
- **Toast placement.** Toasts are capped at 2 and auto-dismiss after 6s. On the table they appear at the top of the table column; elsewhere they appear at the bottom on desktop and at the top on phones.
- **Transfer number.** The spotlight's "Transfer #n" comes from the matching entry in `recentTransfers`, because `askSucceeded` carries no `seq`. The view always arrives before the 0.7s reveal.
- **Timer progress** is `remaining / room.config.turnSeconds`. It doesn't correct for clock skew between client and server.
- **Choose-phase timer.** The ring also shows during choose phases when `turnDeadline` is set, coloured for the chooser's team.
- **Leaderboard order** follows the server (wins descending) and shows at most 20 rows.
- **Action buttons** are disabled after sending until the next `game.view` or `error` arrives, to stop double submits.

## Open questions

1. The server sends no close codes for a WebSocket upgrade rejected with 401 or 404, so the client can't tell an unknown room from a network outage. It retries and shows "Can't reach room X" after 3 attempts. Could the server accept the upgrade and send `error ROOM_NOT_FOUND` before closing, as it does for `ROOM_IN_PROGRESS`?
2. "♛" has no glyph in some minimal font setups (e.g. headless Chromium). Desktop browsers fall back to a system font. Is that acceptable, or should it be replaced with an inline SVG?

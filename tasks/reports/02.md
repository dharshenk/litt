# Task 02 report: server

## Built

- Strict zod schemas for all eight client message types, using engine card/set validators and bidirectional compile-time protocol checks. Rejects malformed JSON, extra/missing fields, invalid config bounds, and payloads exceeding 16 KiB of UTF-8.
- Host-independent `Room`: team/config management, alternating seats, authoritative engine actions, personalized views, one-time events, host hand-off, replacement connections, rejoin, per-move timers, finished-game recording, and rematches.
- `RoomRegistry`: unique four-character codes, collision handling, connection-driven cleanup after 30 empty minutes, and timer disposal on cleanup/shutdown.
- Web-standard Hono routes for authentication, current user, room creation, leaderboard, and individual stats.
- Exported `createDevAccounts`: local name form, validated cookie/query identities, safe local redirects, logout, and in-memory finished-game stats.
- Thin Node adapter: Hono HTTP serving, authenticated `ws` upgrades, real engine wiring, deferred Discord/SQLite account loading, production authentication guard, and graceful shutdown.
- Five Vitest suites with a scripted fake engine and fake timers. No dependencies were added; shared contracts, design files, and other packages were not changed.

## Run

```sh
npm run dev -w @litt/server
```

Default URL: `http://localhost:8787`. Visit `/auth/login` for local sign-in. `PORT` overrides the port.

Without Discord credentials, use `?devUser=Alice` on HTTP and WebSocket requests for independent identities in multiple tabs. Names accept 1-20 ASCII letters, digits, underscores, or hyphens; ids are `dev:<name>`. This parameter overrides the cookie, including when invalid (invalid input never falls back to a cookie identity).

The Node entry selects real accounts when `DISCORD_CLIENT_ID` is set; also supply `DISCORD_CLIENT_SECRET` and `SESSION_SECRET`. `DATABASE_PATH` defaults to `./litt.db`; `PUBLIC_BASE_URL` defaults to `http://localhost:<port>`. Production without Discord configuration refuses to start instead of using fake authentication.

The adapter does not serve the web build. The Vite client should proxy `/api`, `/auth`, and `/ws` to the server, as specified in Task 05.

## Permitted dependency exception

At handoff, `@litt/accounts` still exports only its contract types. `createAccounts` and `@litt/accounts/node` are not yet implemented/exported. The full adapter typecheck reports exactly these two errors in `src/node/main.ts`:

```text
TS2339: Property 'createAccounts' does not exist on the accounts module.
TS2307: Cannot find module '@litt/accounts/node'.
```

As allowed by Task 02, `tsconfig.json` excludes only `src/node/main.ts`; every other source and test file is checked. `tsconfig.node.json` includes the adapter too:

```sh
npm run typecheck:node -w @litt/server
```

Run this additional gate after Task 04 supplies those exports. Real authentication/SQLite behavior is not verified yet. Dynamic imports keep the local dev adapter runnable while that work is pending; no missing exports are suppressed or fabricated.

## Assumptions and small additions

- Added optional `RoomDeps.onConnectionsChanged` so a factory can connect room membership changes to registry cleanup without polling or host-specific logic.
- Added `Room.dispose` and `RoomRegistry.dispose` to cancel game/idle timers and support clean adapter shutdown.
- Newly created, never-joined rooms also expire after 30 empty minutes. A join cancels cleanup; the next last-player departure starts a fresh interval.
- If no connected successor exists when the host leaves, the first subsequent join/rejoin fills the vacant host position. Finished seats/teams survive rematch as specified.
- The wire contract takes precedence over older architecture sketches: emits `room.state`, maps choose intent `player` to engine `choice`, and always sends `turnDeadline` as a number or null.
- Login redirects are restricted to local paths. Duplicate finished-game ids do not double-count dev stats.
